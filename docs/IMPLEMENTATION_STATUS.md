# RReklam — текущее состояние реализации

**Дата:** 28 октября 2026. Сверять с главным ТЗ пользователя и [решениями](DECISIONS.md). Исходники: `main`.

## Уже реализовано в исходном коде

- Next.js App Router, TypeScript, Tailwind CSS; публичные маршруты `/hy`, `/ru`, `/en`.
- Главная, базовые страницы услуг, цен, FAQ, контактов и кейсов. Контент некоторых разделов пока заглушка.
- Форма заказа с несколькими городами, количеством машин в каждом городе, форматом и сроком 7/14/30/90 дней. **Это только клиентский предпросмотр; сервер не принимает заказ.**
- Prisma-схема PostgreSQL: пользователи, роли, водители, автомобили, четыре фото, города, автопарки, кампании, назначения, тарифы, выплаты, аудиторские события.
- Серверная основа NextAuth: Google OAuth, SMS OTP (Twilio), подтверждение телефона для Google-аккаунта. **Не работает без внешних ключей и развернутой БД.**
- Серверная проверка активных ролей, отдельные проверки принадлежности менеджеру на API модерации.
- Заявка водителя и регистрация машины с четырьмя изображениями в приватное S3-совместимое хранилище. Нужны MinIO/S3, БД и авторизация.
- Очередь проверки водителей/машин. Менеджер должен записать, как проверил разрешение собственника, перед одобрением автомобиля.
- API и интерфейс минимальных остатков машин по городам (изменяет только владелец).
- Административная проверка доступности машин на будущий период с учетом пересечений бронирований. Это **предварительная** доступность, без гарантии пригодности для конкретного формата.
- SQL-ограничение PostgreSQL против пересекающихся занятых периодов одного автомобиля.
- Unit-тесты расчёта маржи 25%, доступности, дат. Интеграционный тест PostgreSQL: пересекающиеся назначения отклоняются, соседние разрешены.
- GitHub Actions: установка пакетов, Prisma generate/validate, тесты, tsc, Next build, PostgreSQL интеграция.

## Не реализовано, не обещать пользователям

- Полноценный механизм активации клиентов, создания сотрудников владельцем, собственных кабинетов и переназначения клиентских менеджеров.
- Публикация обязательных договора/согласий, проверка прав на оклейку в соответствии с законодательством Армении.
- Сохранение клиентских заказов в БД, полноценная обработка заказов менеджерами и реальное бронирование из UI.
- Финансовые server actions с обязательными затратами, owner-only исключениями ниже 25%, утверждением скидок, платежным шлюзом, возвратами и бухгалтерией.
- Настоящие тарифы; прошлый Excel содержит примерные стартовые цены. **Не публиковать как подтвержденный прайс.**
- Дневные случайные фотопроверки 09:00–21:00 и 2 часа на ответ, реальное уведомление и контроль новых фотографий.
- Согласованный чат, email/SMS/on-site-уведомления, согласованные клиентские отчеты.
- Полный справочник всех населенных пунктов Армении (пока сидированы 10 марзов, Ереван и 10 административных центров).
- Исторический календарь с интерфейсом ручного назначения, ежедневные резервные копии БД и медиа, полноценный PWA.
- Полностью переведённый интерфейс (внутренние кабинеты частично на английском), дизайн всех публичных разделов и юридические страницы.
- Нагрузочное тестирование, внешняя проверка безопасности и production deployment.

## Технические ограничения

- Первый запуск требует PostgreSQL, приватного S3/MinIO, переменных окружения и миграции.
- Для разработки Docker Compose использует **небезопасные тестовые учётные данные**; не подключать к публичному интернету.
- Изоляция/права проверяются на существующих API, однако это не замена полному security-аудиту.
- Отчёты «мало машин» отображаются в админ-панели, но автоматические уведомления ещё не отправляются.
- PostgreSQL exclusion-constraint необходимо применять после создания таблиц. CI проверяет это с реальной БД.
- Учёт оклеенных машин и совместимости форматов требует дальнейшей доработки статусов и бизнес-правил.
