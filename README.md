# RReklam

Платформа автомобильной рекламы для Армении. Частные водители, такси и автопарки; агентство — посредник. Армянский язык по умолчанию, русский и английский дополнительно.

**Статус: MVP в разработке, не готов к публичному запуску.** [Что реализовано](docs/IMPLEMENTATION_STATUS.md) · [Наши решения](docs/DECISIONS.md).

## Ошибка Docker: `pull access denied for minio/mc` (Windows)

Исправлено в исходном `docker-compose.yml`: MinIO server и MinIO client теперь берутся из `quay.io`, потому что Docker Hub больше не предоставляет прежние имена образов.

В PowerShell из папки репозитория:

```powershell
git pull --ff-only
docker compose pull
docker compose up -d
docker compose ps
```

Если нужно только подключить PostgreSQL для инициализации владельца, можно сначала выполнить `docker compose up -d postgres`. Создание роли OWNER требует уже зарегистрированного аккаунта с подтверждённым телефоном. Простой запуск Docker не создаёт владельца автоматически.

После первого запуска базы выполняйте миграцию, заполнение справочников и установку SQL-ограничений по инструкциям ниже. Не выполняйте повторно SQL-скрипт, если ограничения уже созданы. MinIO Init — одноразовый контейнер; статус `Exited (0)` после создания бакета ожидаем.

## Быстрый локальный вход владельца без Google/SMS (только для просмотра на своём ПК)

Если PostgreSQL уже запущен (`docker compose ps` показывает `postgres ... healthy`), Google и SMS пока не нужны. Для этого в коде есть **строго локальный тестовый вход**.

1. Скачайте изменения `git pull --ff-only`; не перезаписывайте собственный `.env`.
2. В `.env` задайте `AUTH_SECRET` (случайная строка), `RREKLAM_LOCAL_DEMO="true"` и `RREKLAM_LOCAL_DEMO_PASSWORD="<случайный пароль длиной минимум 20 символов>"`. Не добавляйте эти значения в GitHub.
3. Выполните `npx tsx scripts/bootstrap-local-owner.ts` из корня проекта. Требуется уже созданная локальная база (`npm run db:migrate -- --name init` и `npm run db:seed` при первом старте).
4. Запустите `npm run dev`, откройте `http://localhost:3000/ru/login`, в блоке **Тестовый вход владельца** введите свой пароль.
5. Перейдите на `http://localhost:3000/ru/admin`.

**Ограничения безопасности:** провайдер доступен только при `NODE_ENV=development`, явном флаге, сильном пароле, локальной PostgreSQL и запросе с localhost/127.0.0.1. Если уже создан другой владелец, script не захватывает его роль. Для production тестовый вход отключается; не переносите эту тестовую базу с фиктивным подтверждением телефона в рабочую среду. Перед запуском для клиентов отключите `RREKLAM_LOCAL_DEMO` и используйте реальные Google/SMS.

**Если после нажатия «Войти как владелец» в PowerShell выводится `CredentialsSignin`:** запрос дошёл до Auth.js, но локальный вход был отклонён. Проверьте `http://localhost:3000/api/dev/local-owner-status`; значения `localDemoEnabled`, `ownerCreated`, `ownerActive` должны быть `true`. После обновления кода повторите вход: PowerShell с `npm run dev` напечатает безопасную подсказку `[RReklam local login] DENIED: ...`. Проверка пароля использует ровно строку `RREKLAM_LOCAL_DEMO_PASSWORD` из `.env` (не `BOOTSTRAP_OWNER_EMAIL`). После изменения `.env` перезапускайте `npm run dev`. Пароль, `AUTH_SECRET` и другие секреты не присылайте в чат.

**Если Docker выдаёт 401 для MinIO:** не запускайте пока медиа. `docker compose up -d` поднимет только PostgreSQL, поскольку медиа вынесены в отдельный профиль `media`. Вход владельца и изучение панели не требуют MinIO. Загрузка фотографий водителей без хранилища не будет работать.

## Первый локальный запуск

Нужно: Node.js 22+, npm и Docker с Compose. Данные в `docker-compose.yml` — только для локальной разработки; не публикуйте их в интернете.

```bash
git clone https://github.com/Rob1-997/rreklam.git
cd rreklam
npm install
cp .env.example .env
docker compose up -d
npm run db:generate
npm run db:migrate -- --name init
npm run db:seed
npx prisma db execute --file prisma/sql/booking_constraints.sql --schema prisma/schema.prisma
npm run dev
```

Открыть http://localhost:3000, маршруты /hy, /ru, /en. На сайте работает предпросмотр заявки. Авторизованные пользователи с подтверждённым телефоном могут отправить предварительный запрос на несколько городов; менеджер увидит его в своей очереди. **Это не подтверждённый заказ, не бронирование и не оплата.**

В Windows вместо `cp` используйте `copy .env.example .env`.

### Настройка авторизации

В `.env` необходимо задать реальные, **секретные** значения (никогда не отправлять их в чат и не коммитить в GitHub):
- `AUTH_SECRET` — криптографически случайная строка (например, `openssl rand -base64 32`).
- `OTP_PEPPER` — независимый случайный секрет длиной от 32 символов.
- `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` — OAuth Google.
- `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` — провайдер SMS; перед запуском проверить поддержку доставки в Армению, цены и нормативные требования.
- `DATABASE_URL` — PostgreSQL, `S3_*` — приватное хранилище фотографий. Compose поднимает локальный MinIO с тестовыми настройками.
Без подключённых Google/SMS авторизация не будет работать, а без S3 — нельзя отправить четыре фотографии.

Аккаунт, вошедший через Google, должен подтвердить телефон; после этого может подать заявку водителя. Активация роли PERFORMER выполняется менеджером или владельцем через защищённый API.

### Первоначальный владелец

Зарегистрируйте через Google пользователя с Email, подтвердите телефон. Только затем локально задайте `BOOTSTRAP_OWNER_EMAIL` в `.env`, а `BOOTSTRAP_CONFIRM=GRANT_INITIAL_OWNER`. Один раз выполните:

```bash
npx tsx scripts/bootstrap-owner.ts
```

Сразу удалите временную переменную подтверждения из `.env`. Bootstrap блокируется, если активный владелец уже существует. **Не запускать на неподготовленной production-базе.**

## Тарифы и сметы (в разработке)

- `/hy/prices` — только тарифы, официально утверждённые владельцем; значения из демонстрационной модели не публикуются автоматически.
- `/hy/orders` — свои предварительные заявки и коммерческие предложения; **кнопки оплаты нет**.
- `/hy/admin` — владелец устанавливает цены и ставки водителей, рассматривает предложения менеджеров и сметы со скидкой или маржинальностью ниже 25%.
- Менеджер видит только назначенные заявки, вводит расходы вручную по всем обязательным категориям и подготавливает версионную смету. Утверждённые тарифы подтягиваются с сервера, а не из полей браузера.
- При **нулевой скидке** и **марже от 25%** смета может пройти стандартное автоматическое согласование в системе. **Любая скидка** или **маржа ниже 25%** требует решения владельца с причиной. Оплата и резервирование машины этим не выполняются.
- Новая версия сметы не создаётся, пока предыдущая ожидает владельца. Каждая смета хранит снимок утверждённых цен и затрат, поэтому последующее изменение тарифа не затрагивает расчёт.
- В основе суммы **AMD** (целые драмы); маржинальность по прямым расходам не равна чистой прибыли. Налоги и накладные расходы ещё не включены в проектный расчёт.

## Кабинеты и API

- `/hy/driver` — водитель: заявка, машины, четыре фото, статусы модерации.
- `/hy/admin` — OWNER/MANAGER: очередь заявок, решение с проверкой прав собственника, запас машин и проверка доступности на будущие даты.
- `/api/locations`, `/api/body-types` — справочники для разработки.
- `/api/driver/profile`, `/api/vehicles` — защищённая регистрация.
- `/api/client/campaigns` — подача предварительного запроса с несколькими городами после входа и подтверждения телефона; утверждение стоимости и оплата не подключены.
- `/api/admin/campaigns` — только заявки клиентов назначенного менеджера (владелец видит все).
- `/api/admin/tariffs`, `/api/admin/tariffs/proposals`, `/api/admin/tariffs/proposals/[id]/decision` — цены, предложения менеджеров, утверждения владельца.
- `/api/admin/campaigns/[id]/quotes` — сметы с серверной проверкой расходов, ставок и прав менеджера; `/api/admin/quotes/pending` и `/api/admin/campaigns/[id]/quotes/[quoteId]/decision` — очередь и решения владельца.
- `/api/public/tariffs` — только публичная утверждённая цена, никогда не ставка водителя или количество свободных машин.
- `/api/admin/vehicles`, `/api/admin/drivers`, `/api/admin/stock`, `/api/admin/availability` — только для активированных сотрудников.

Не загружать реальные документы водителей в тестовую среду. Отдельно согласовать публикацию условий, политик хранения данных и юридических согласий.

## Финансовые правила

- Все суммы в AMD; владелец утверждает базовые тарифы и изменения.
- Любая скидка требует утверждения владельцем.
- Минимальная маржинальность 25%, исключения утверждает владелец с причиной.
- Клиент оплачивает 100% заранее; платежи ещё не подключены.
- Водитель получает индивидуальные выплаты по утверждённым ставкам; пропуск проверки лишь предупреждает.
- Предварительные коммерческие цены из прежних файлов **не утверждены**.

## Ограничения

Это заготовка работающего продукта, не действующий рекламный маркетплейс. Перед запуском ещё нужны реальные заказы, система менеджеров, проверка прав, финансовые операции, отчётность, чат, законные согласия, безопасность и ежедневные резервные копии.
